- (constraint) Inherited from PRD: single user, laptop browser, no accounts/mobile; both guitar and piano views; audio synthesis required; no mic/MIDI input; no scoring
- (direction) Coaching path; spine is the only deliverable (explainer later if wanted)
- (decision) Sound: hybrid. Audio sits behind one interface (play notes on instrument as block/arpeggio/strum). Ship pure Web Audio synthesis first; sampled instruments in a later phase. Binds all playback; prevents UI code touching audio nodes directly
- (decision) Stack: TypeScript + React (user has 6 years web dev, explicitly chose). State management and tooling details still open
- (question) Physical-model synthesis (Karplus-Strong guitar, additive piano) explained to user out of curiosity; not chosen
- (decision) Paradigm: framework-free TS music-theory core + audio engine behind interface + thin React UI. Dependencies point inward (UI -> core/audio; core knows neither). Prevents theory logic leaking into components
- (decision) State: React Context + reducer, split contexts (settings vs session), plain serializable state. Playback is a command to the audio engine, never React state. Zustand/Jotai only if Context demonstrably hurts (Rule of Three)
- (decision) Pitch: core stores integers only (MIDI note number absolute, pitch class = n mod 12, interval = semitone count); no note-name strings in core
- (decision) Spelling: context-aware display layer. Chord tones spelled by letter-name stepping from the spelled root; root spelling comes from user pick or default table
- (decision) Voicing: one representation (ordered absolute pitches bass->treble; guitar adds string/fret assignment). Generation = pure core function returning every playable voicing, unranked. Ranking = separate function: register match (FR-18) plus common-shape-first (FR-17)
- (decision) Common shapes via curated templates (user chose over scoring heuristic). Templates are a data file, movable shapes defined relative to root, open shapes fixed; non-template playable voicings still listed after. A test asserts every template yields the right pitch classes
- (constraint) MAINTENANCE: curated shape templates must be updated by hand when new chord qualities are added (user asked to note this); each new quality needs templates or it falls back to generated-only
- (decision) Environment: static client-side app (Vite + React + TS), run locally via dev server; no backend; hostable later as static site with no changes. Settings may persist in localStorage only
- (decision) Guitar: 6 strings, standard tuning EADGBE, 22 frets; tuning is a core parameter (alternate tunings later, not a rewrite)
- (decision) Testing: Vitest on the core (logic and risk live there), light component tests, no e2e. Audio engine starts on first user gesture, no enable-sound screen
- (direction) Next: verify current versions (React, Vite, TS, Vitest, Node) on web, then distill spine
