## Findings

### Spec-to-implementation reconciliation

1. **The epic text described a display Apor did not want.** Story 4.1 as written asked for every position of each chord note (`epics.md` Story 4.1, PRD FR-15, `EXPERIENCE.md:105` marked `[ASSUMPTION]`). It surfaced only while drafting the 4.1 spec and led to the sprint change proposal. Disposition: fixed (retired 4.1, reworded FR-15 and the UX docs, commits `85d7ce7`, `decd9b0`, `0df53be`). Lesson: a planning assumption that no one confirmed with a picture of the result reached the epic list; confirm the visible behaviour with an example before breaking an epic into stories.
2. **The voicing rules were found by trying the result, not from the spec.** After implementation Apor corrected the shapes six times: root or bass lowest (`spec-4-3` Boundaries), no muted string between sounding ones, open strings only at or below fret 5, register bucket 6, more sounding strings first, then at most four fingers with a barre rule, the 5th required on triads, no fret above 12 (`epic-4-decisions-for-review.md`, commits `220674c`, `a2a9d68`). Each correction came from Apor naming real fingerings (`x 3 2 0 1 0`, `8 10 10 9 8 8`, `x 3 5 5 5 3`). Disposition: fixed. Lesson: a generation and ranking story needs golden examples in its matrix (the first voicing for C, Am, G7, Cmaj7 in a stated register), reviewed by the owner before build.
3. **Epic text is now stale against the code.** `epics.md` Story 4.3 still says "only the 5th droppable" and lacks the finger rule, `maxFret` and bucket width 6 (`epics.md:1087`); PRD FR-17 says "reachable fret span, essential chord tones present". Disposition: propose reconciliation (action item 1).
4. **Accepted deviations (recorded so later retros stop re-flagging them):** Block strums only when a guitar voicing is shown, the buttons keep their labels (`spec-4-7` triage row 5); the no-voicing Status text is `No voicing fits these notes.` and is unreachable for a named chord, so it is tested only through a mocked generator (`ExploreNoVoicing.test.tsx`); the stepper row grew the shared block height by 40 px, so the instrument sits at 366.2 px instead of 312.2 px in Explore and Listen (`spec-4-4` decision 3); an open C7 template leaves out the 5th (`spec-4-5` triage).

### Duplication map and pattern divergence

5. **The voicing list is computed in many hooks.** `useShown` (via `useVoicingList` and `useLitNotes`) runs in `App.tsx:34`, `ExploreView.tsx:29`, `VoicingStepper.tsx:13`, `GuitarStage.tsx`, `PianoStage.tsx:10`, `useSessionActions.ts:20` and `useShortcuts.ts:37`, and `useSessionActions` is itself called from many components, so one change recomputes generation and ranking in every instance. Three reviews flagged it (`spec-4-4` triage row 8, `spec-4-7` triage row 3) and each rejected it as small; the evidence of cost is that `ExploreStepper.test.tsx` needed its timeout raised to 20 s in Story 4.6 (diff `82e9707..f447773`). No lag was seen in Chrome. Disposition: defer (action item 2).
6. **`bestVoicing` re-derives which reading to use** with `orderedReadings` and `readingRootedOn` next to `exploreReading` (`useLitNotes.ts`), rather than reading it from one place (`spec-4-3` triage row 12). The same helpers are used, and a chosen-root test pins it. Disposition: accept, revisit if the provider in item 2 is built.
7. **Pattern divergence:** none found. `npm run check` (import boundaries) passed after every story; new files follow the existing layout (`core/voicings.ts`, `core/shapes.ts`, `ui/explore/VoicingStepper.tsx`). One stray whitespace edit on an untouched line was caught by all three reviewers (`spec-4-7` triage row 1), which is the AGENTS.md no-reflow pitfall.

### God-class and size growth

8. **No god-class.** Largest source files after the epic: `session.ts` 235 lines, `useLitNotes.ts` 170, `useSessionActions.ts` 162, `voicings.ts` 150 (`wc -l`). Largest churn is in tests: `tests/core/voicings.test.ts` +336, `ExploreEdit.test.tsx` +234, `ExploreStepper.test.tsx` +182 (`git_evidence.py`). Disposition: accept.

### Review lenses (from the stories' triage logs)

9. **Review findings were mostly test quality, not defects.** Across the five triage logs, nearly every `patch` row was a tautological or loosened assertion, a missing branch test or a deleted assertion (`spec-4-3` rows 1 to 9, `spec-4-4` rows 1 to 6, `spec-4-5` rows 1 to 3, `spec-4-6` rows 1 to 5). Real behaviour fixes were few: the `editVoicing` and `selectVoicing` guards, the announcer clearing, the shortcut list entry. Lesson: the implementer should be told up front to assert exact outcomes (no assertion that cannot fail, never loosen a test to pass); that would remove most of the review loop.
10. **Rejected findings kept recurring** (hook cost, `aria-disabled` on a span, hard-coded 5th index, bucket width guards). Dispositions are in the logs; the pattern suggests adding them to AGENTS.md pitfalls only if they come back in Epic 5.
