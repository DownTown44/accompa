## Intent

**Problem:** The ranked list (4.3, 4.4) orders by register, string count and fret span only, so the shapes Apor names (open C `x 3 2 0 1 0`, the E-shape barre `8 10 10 9 8 8`, the A-shape barre `x 3 5 5 5 3`) can sit among odd or fragmentary voicings.

**Approach:** Shape templates as data in `core`; `rankVoicings` puts a template match ahead of the other voicings of its register bucket. The generator, bucket width and rules are unchanged.

## Boundaries & Constraints

**Always:** New `core/shapes.ts`, pure, data only. A template is `{ quality, kind, frets, root? }`: `frets` has one entry per string, lowest first, a number or `null` (muted), and `quality` is a `CHORD_QUALITIES` name. A `movable` template holds frets relative to its anchor, the lowest sounding string, whose note is the root; it is instantiated for a root with the anchor fret in 1 to 12, dropping instances that go below fret 1 or above the neck. An `open` template holds absolute frets and a `root` pitch class and applies only to that root. No fingering. `shapeFrets(chord)` returns the instantiated fret arrays for the chord's root and quality, `[]` when the quality has none.

Shapes (decided, recorded for Apor's review): movable E-shape `0 2 2 1 0 0` and A-shape `x 0 2 2 2 0` for major; `0 2 2 0 0 0` and `x 0 2 2 1 0` for minor; the sevenths of both shapes (7, m7, maj7); a "3 note variant" read as the top triad on the G, B and high E strings (major `x x x 0 0 -2`, minor `x x x 0 -1 -2`). Open shapes: C, A, G, E, D major; Am, Em, Dm minor; C7, G7, D7, E7, A7, Am7, Em7, Dm7, Cmaj7, Amaj7, Fmaj7, Dmaj7. Diminished, augmented, m7b5 and dim7 have no templates yet and fall back to generated voicings only, with no error.

A voicing matches when its `frets` equal an instantiated template (same strings, muted strings equal). Ranking key order: register bucket, then template match (matches first), then more sounding strings, then the existing span, distinct-frets, distance and generator keys. A match from an open template counts only in bucket 0 (the same distance rule as the bucket, so within the source register); elsewhere it ranks as a non-match. A movable match counts in any bucket. Non-matches follow the matches within their bucket, unchanged in order. `rankVoicings` takes the chord's shape frets as an optional fourth argument (default none, so Story 4.3 callers keep their result); `useLitNotes` passes `shapeFrets` of the lead reading. A shape is shown only if the generator produced it (bass, span 4 and open-position rules still hold); a test asserts every instantiated template is generated for its chord.

Every template yields exactly its chord's pitch classes (test, all roots, no extra, none missing).

**Never:** No stepper change, no hand-edit (4.6), strum (4.7), shape labels, new Workspace field, or reducer action; no change to the generator, `VOICING_RULES`, `nameChord`, `placeLit`, Listen or Play; no touch, phone or narrow-viewport handling.

## Design Notes

Templates are data so a new shape needs no logic. Anchor fret for a root is `(root - pitchClass(tuning[anchor]) + 12) % 12`, with 0 read as 12; fret 0 belongs to the open templates.
