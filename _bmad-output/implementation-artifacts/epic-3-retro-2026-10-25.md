## Findings

Every finding below was checked against the file, commit or run named. Reviewer claims that did not hold up stay in each story's triage log, not here.

### Behavior and boundaries between stories

1. **The one real defect in review was a Listen regression from the shared marker.** Story 3.2's `PianoKeyboard` and `Fretboard` gave a lit non-root note the new r5 dot and the piano root key the new tint when `roles` was omitted (Listen). The spec said Listen is unchanged. The edge-case and blind reviewers found it (`spec-3-2-...md` triage rows 1 and 3); my browser check did not look at Listen's dot size. Fixed with a `plain` marker path and a Listen test. Disposition: **accept** (fixed).
2. **The screen grew 80px of reserved rows, by design.** The instrument top edge went from 216px (Explore) and 232px (Listen) at the end of Epic 2 to 231.59, 264.19 and 312.19px as the readout block grew to hold the legend (3.2) and the alternatives row (3.3). Every story measured the top edge equal in every state (matrices in 3.2, 3.3, 3.5, 3.6). Listen shares the height, so it shows an empty band above the instrument. Disposition: **accept** as recorded in the specs; see Behavior verification for the fit check.
3. **Stories were designed in a different order than the code needed.** 3.3's reading choice and 3.6's chosen root both write the workspace; 3.6 had to settle how `Workspace.root` and `Workspace.reading` combine, which neither epic text nor 3.3's spec decided (`spec-3-6-...md` frozen block). It worked because 3.3 left the combination as a written open point. Disposition: **accept**.

### Duplication and size growth

Story 3.3's reviewers raised the first instance and it was rejected as low in isolation (`spec-3-3-...md` row 3); 3.6 added two more.
